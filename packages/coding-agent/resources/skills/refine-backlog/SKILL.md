# Skill: refine-backlog

## When to Use
Apply this skill when shaping requirements, breaking epics into sprint-ready stories, establishing domain language, or defining acceptance criteria.

## Backlog Refinement Procedure

1. **Establish Ubiquitous Language (DDD)**:
   - Agree on standard domain terms between business and engineering.
   - Create a glossary of entities, actions, and actors to eliminate terminology ambiguity.

2. **User Story Slicing (INVEST Standard)**:
   - Ensure stories are Independent, Negotiable, Valuable, Estimable, Small, and Testable.
   - Structure stories clearly: *As a [user persona], I want [action/capability] so that [business value]*.

3. **Verifiable Acceptance Criteria (BDD Specification by Example)**:
   - Write acceptance criteria in Given-When-Then format covering normal flows, edge cases, and validation rules.
   - Define explicit Definitions of Ready (DoR) and Definitions of Done (DoD).
