# Skill: define-technical-direction

## When to Use
Apply this skill when defining cross-team engineering standards, drafting technical RFCs, evaluating new technology adoption, or tackling systemic technical debt across an organization.

## Strategic Direction Guidelines

1. **Diagnose Systemic Root Causes**:
   - Look beyond individual symptoms to diagnose architectural friction, fragmented tooling, or misaligned development workflows.
   - Frame technical strategies around measurable business outcomes and team velocity.

2. **Author Requests for Comments (RFCs)**:
   - Structure clear, persuasive RFCs:
     - Problem Statement & Motivation.
     - Proposed Solution & Architecture Guardrails.
     - Alternatives Explored & Trade-Offs Accepted.
     - Migration Roadmap & Rollout Strategy.
   - Build organizational consensus through empirical evidence and transparent trade-offs.

3. **Establish Engineering Guardrails**:
   - Define "Golden Paths" that make the secure, maintainable approach the easiest path for teams to adopt.
   - Provide standard templates, automated linters, and reusable libraries that multiply developer leverage.
